# Benchmark concurrentiel — Portfolios créatifs

Veille factuelle 2024-2026. Aucun design, code ni visuel copié. URLs consultées directement (ou état documenté).

## Références françaises

- **bruno-simon.com** — portfolio « monde 3D jouable » ; transparence technique (stack, devlogs, code MIT) comme argument de vente ; options réelles (audio, qualité, respawn) ; contrôles mobiles documentés.
- **wodniack.dev** — punchline `"Coding my way since 1987"`, liste datée des projets, `Available for freelance work →` dès le hero, email visible, toggle de contraste.
- **thomasaufresne.com** — liste numérotée 01→17, **crédits de collaborateurs affichés** (« WebGL by … ») : l'honnêteté remplace le storytelling.
- **clementgrellier.fr** — proposition de valeur en une phrase, `Skip to main content` présent.
- **antonin.space** — une page épurée, disponibilité affichée, listes nominatives d'agences et de clients.
- **robin-noguier.com** — référence des études de cas approfondies (problème → contribution → décisions → résultats).
- **corentinbernadou.com** — identité « designer AND developer », esthétique éditoriale/magazine (« Issue N°01 »), périmètre des missions explicite.

## Références internationales

- **elliott.mangham.dev** — credentials chiffrés dès la 1re page, prix moyens publiés, CTA construits (calendrier), écrans mobiles dédiés.
- **art-yakushev.com** — 8 projets avec pages case study, secteur/positionnement de chaque client, workflow + FAQ.

## Bonnes pratiques convergentes

1. La preuve avant la décoration (chiffres, noms, crédits > adjectifs).
2. Proposition de valeur en une phrase dès le premier écran.
3. Transparence des collaborations et du périmètre exact.
4. Disponibilité + chemin de contact visibles en permanence.
5. Peu de projets, approfondis (3–8) plutôt qu'un mur de thumbnails.
6. Études de cas qui commencent par le résultat.
7. Accessibilité et options d'affichage comme signal de qualité.
8. Animations/3D en option, jamais imposées ; LCP maîtrisé.
9. Mobile repensé (contrôles documentés, ~60 % du trafic).
10. Transparence de process/stack comme différenciateur.

## Anti-patterns à éviter (cf. anti-patterns.md)

Bento systématique, glassmorphism générique, marquee permanent, curseur custom décoratif, preloader artificiel, scroll hijacking, animations continues, jargon vide, dark mode mécanique mal contrasté.

## Carte d'opportunités

1. Étude de cas éditoriale type article de fond (rare chez les creative developers FR).
2. Honnêteté : dire ce qui n'a pas marché, contraintes réelles, périmètre exact.
3. Comparaison desktop/mobile dans le cas d'étude (méta-démonstration du responsive).
4. Publier ses vraies métriques de performance (CWV, poids de page).
5. Accessibilité affichée comme signature (skip-links, focus, reduced-motion).
6. Positionnement explicite « direction artistique + dev front ».
7. Version FR soignée (marché sous-servi) avec EN prêt.
8. Contact et disponibilité sticky.

## Décisions dérivées pour le portfolio

- Cadre **éditorial clair**, études de cas structurées et profondes.
- Chaque carte projet : rôle, année, secteur, statut (client/concept), crédits si partagés.
- Contact accessible en permanence (header/footer + CTA).
- Métriques de performance réelles publiées dans la page About (honnêtes, vérifiables).
- Aucun anti-pattern listé ci-contre.
